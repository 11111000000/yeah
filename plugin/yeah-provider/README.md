# yeah-provider — агент Yeah в Paseo

Плагин Paseo, который регистрирует **провайдера ACP** и поднимает ACP-сервер
ядра [Yeah](https://github.com/11111000000/yeah) в Emacs. После установки в
Paseo появляется агент **Yeah** — как любой другой: его выбирают в списке
агентов, и он работает в рабочем каталоге, который открыт в Paseo.

Ядро Yeah — это агентный harness на Emacs Lisp: модель достаётся через gptel,
эффекты идут через реестр инструментов и систему разрешений, а журнал сессии
остаётся append-only JSONL. Провод — ACP (JSON-RPC поверх stdio).

## Где лежит плагин

**Плагин — часть репозитория ядра:** `plugin/yeah-provider/` рядом с `lib/`,
`tests/` и `docs/`. До 2026-11-18 он жил вне репозитория
(`/home/az/Projects/PaseoPlugins/yeah-provider`) и не был под контролем версий;
решение владельца — держать его здесь, чтобы правки плагина и правки ядра
жили в одной истории.

Собранный бандл не знает, где он лежит (демон Paseo выполняет его через
`eval`, и `__dirname` в нём не определён), поэтому корень ядра приходит
извне: переменная окружения `YEAH_REPO_PATH`, а иначе — настройка `repoPath`.

## Установка

```sh
paseo plugin install /home/az/Projects/yeah/plugin/yeah-provider
```

Требуется `pluginsEnabled: true` в конфигурации демона (уже так) и живой
`~/.paseo/config.json`. Путь к ядру, модель и профиль разрешений — в
настройках хоста (Paseo → Settings → Yeah).

## Настройки

| Поле | По умолчанию | Смысл |
|---|---|---|
| `repoPath` | `YEAH_REPO_PATH` или `/home/az/Projects/yeah` | корень ядра; `lib/` оттуда грузится |
| `gptelPath` | `""` | каталог сборки gptel; пусто — свежайшая в `~/.emacs.d/elpa` |
| `emacsPath` | `""` | путь к Emacs; пусто — ищется в известных местах |
| `model` | `MiniMax-M3.1-Flash` | модель провайдера |
| `host` | `api.minimax.io` | хост провайдера |
| `profile` | `build` | `build` спрашивает человека, `plan` запрещает правки |
| `keyFile` | `~/.config/yeah/live.env` | файл окружения с ключом провайдера |
| `dataHome` | `""` | каталог данных Yeah; пусто — умолчание ядра |

### Ключ провайдера

Ключ **не хранится** в настройках плагина и не попадает в конфигурацию
Paseo. Он лежит в файле окружения вне дерева репозитория (режим `0600`):

```sh
# ~/.config/yeah/live.env
export YEAH_TEST_KEY=...
export YEAH_TEST_HOST=api.minimax.io
export YEAH_TEST_MODEL=MiniMax-M3.1-Flash
```

Плагин читает `YEAH_ACP_KEY` или `YEAH_TEST_KEY` из этого файла (путь
настраивается) и передаёт ключ процессу ACP через окружение. Значение ключа
не печатается и не сохраняется плагином.

Если `YEAH_ACP_KEY` уже есть в окружении демона, файл не читается вовсе.

## Как это работает

1. Плагин регистрирует провайдера `yeah` через `runAcpProvider` — с
   **коннектором**, а не с командой запуска.
2. Коннектор сам поднимает процесс ACP: Emacs в пакетном режиме с `lib/`
   ядра и каталогом gptel в `load-path`, бэкендом модели через gptel,
   профилем разрешений и `yeah-acp-serve`.
3. Причина — в окружении демона: `ProviderRuntime.resolveLaunch()` собирает
   окружение процесса из настроек демона, и `YEAH_*` до процесса не доходят.
   С коннектором плагин вызывает `spawnProcess` сам и отдаёт демону поток
   провода (`ndJsonStream` из `@agentclientprotocol/sdk`).
4. Всё живое — в окружении (`YEAH_ACP_LIB`, `YEAH_ACP_GPTEL`,
   `YEAH_ACP_MODEL`, `YEAH_ACP_HOST`, `YEAH_ACP_KEY`, `YEAH_ACP_PROFILE`,
   `YEAH_ACP_DATA_HOME`); команда статична, поэтому смена настроек не
   требует пересборки команды и перезапуска плагина.
5. Провод: `initialize` → `session/new` → `session/prompt`. Ответ приходит
   как `session/update`, а вопрос о разрешении — как `session/request_permission`.

### Модель в каталоге провайдера

Ядро по ACP модель не публикует, поэтому `create_agent` с `provider: "yeah"`
отвергался схемой MCP. Модель публикует плагин: трансформер `discover`
добавляет её в каталог провайдера, трансформер `configure` принимает запрос на
эту же модель, а запрос на чужую честно падает.

### Род вызова инструмента

У `tool_call` в ACP есть поле `kind` (род вызова), и ядро его не заполняет.
Род ставит плагин по имени инструмента: `edit`, `read`, `search`,
`execute`. Так интерфейс Paseo показывает вызовы по-разному.

### События очереди

У Yeah есть свои события очереди сессии (`input_queued`, `input_taken`,
`input_recovered`, `input_withdrawn`), и в ACP их нет. Клиент объявляет их в
`_meta` своих возможностей при `initialize` — Paseo не объявляет, и получает
чистый ACP.

### Кодировка провода

Провод — UTF-8, и байты сообщения уходят как есть: русский ответ агента
приходит в Paseo читаемым. Раньше Emacs читал байты unibyte-строки как
Latin-1 и писал их обратно как UTF-8, и весь не-ASCII текст приходил
кракозябрами (дефект ядра, волна 40).

## Что ограничено по проводу

Это ограничения ядра Yeah, а не плагина; плагин их не обходит и не прячет.

- **Отмена.** По stdio отмена читается только после того, как текущий
  промпт дошёл до конца: кнопка «стоп» в Paseo ждёт конца хода. Сокетный
  транспорт ядра эту границу снимает (`yeah-acp-serve-socket`), и переход на
  него — работа плагина, а не ядра.
- **Профиль и модель не переключаются на лету.** `session/set_mode` и
  `session/set_config_option` ядро не знает: профиль выбирается при старте
  процесса, модель — там же.
- **`mcpServers` игнорируются.** Ядро не берёт инструменты от оркестратора.
- **Вызовы инструментов без диффа.** Ядро шлёт в `tool_call` аргументы
  вызова (`rawInput`), а в `tool_call_update` — результат (`rawOutput`), но
  аргументы приходят **позиционным списком значений**, а не именованными
  полями. Paseo читает `filePath`/`oldString`/`newString`, поэтому дифф
  правки в UI Paseo не появляется.
- **Рабочий каталог сессии не применяется к инструментам.** Относительные
  пути агента считаются от рабочего каталога процесса Emacs, а не от `cwd`
  задачи: в живой проверке `bash` агента выполнился в каталоге установки
  CLI Paseo.
- **Журнал — источник истины.** ACP проецирует 8 из 17 типов событий; что
  было в прогоне (нудж, `unfinished`, `usage`, дочерние агенты) — в JSONL
  по адресу `<dataHome>/yeah/projects/<хэш каталога>/sessions/<id>.jsonl`.
