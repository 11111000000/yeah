называет неиспользованный инструмент следующим вызовом. Nudge после плана не

Перезапустить шесть живых проверок после волны 21 и обновить даты в

### Порядок и риски

**P0 → (P5, если есть ключ) → P1 → P2 → P3 → P4.**

- P0 снимает риск потери работы; риск: «большой коммит» — лечится разбиением на
  шесть по пункту 1.
- P1 рискует превратиться в «тест, который мигает»: лечится сравнением по
  структуре, а не по пикселям, и фиксацией версий в самой проверке.
- P2 без решения владельца о пороге остаётся измерением, а не достижением; это
  нормально — измерение честнее заявления.
- P3 — единственный пункт, который агент не должен решать сам.

## 8. Проверка, на которую стоит опереться

```
./scripts/dev byte-compile-all          # ядро компилируется чисто
./scripts/dev ert tests/unit/*.el       # 358 тестов
./scripts/dev check tests/checks/*      # 53 канарейки, с временем каждой
./scripts/dev bench                     # набор задач измерим, успех не выдуман
./scripts/dev map                       # 74 claim'а, 22 uncovered
./scripts/dev gate                      # run + map; вердикт метода
```

Полный прогон занимает около шести минут: в этой среде `./scripts/dev gate`
прошёл за 359 с (12:41:22–12:47:21 UTC). Время съедает фаза отрицательных
контролей, а не сами проверки. Прогон длиннее двух минут стоит запускать в
отдельной дочерней сессии: процесс, начатый прямо из основной, здесь гибнет.

## 9. Правила процесса, которые сессия показала своими граблями

1. **Один прогон метода за волну.** Новый прогон — только с новой причиной.
2. **Не опрашивать фоновые задачи.** Уведомление о завершении приходит само;
   опрос съел четверть вызовов сессии.
3. **Контроли проверять скриптом**, а не на глаз: шаблон `sed` — литерал, а не
   регулярка; именно из-за этого два контроля молча не кусались.
4. **Финальный ответ человеку — всегда**, даже если фоновая задача упала:
   человек должен знать, что сделано, что проверено и что нет.
5. **Коммитить волну** и обновлять доказательства после коммитов.
6. **Заранее объявлять бюджет прогона**; при превышении — отчёт с числами, а не
   бесконечный повтор.
7. **Длинный прогон — в отдельную дочернюю сессию.** В этой среде процесс,
   запущенный прямо из основной сессии, гибнет примерно на второй минуте;
   полный гейт (359 с) дошёл до конца только из дочерней сессии.
